# VocabX — для розробників

Технічний опис проєкту: запуск, структура, ключові рішення. Опис застосунку для користувачів — у [README](../README.md).

> Статус: **фаза A, етап A5** — одна велика колода за ступенем забування (без денних лімітів),
> повторення в оболонці застосунку, колоди й слова (створення, підказки перекладів, порядок,
> архів, повторення окремої колоди), налаштування навчання, онбординг, панель зсуву часу.

## Зворотний зв'язок і аналітика

Змінні середовища (локально — `apps/web/.env`, на Vercel — у налаштуваннях проєкту):

| Змінна                                                           | Для чого                                                                  |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `GOOGLE_CLIENT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `GOOGLE_PROJECT_ID` | сервісний акаунт Google (Sheets API, Cloud Translation API)               |
| `GOOGLE_SPREADSHEET_POLLS_ID`                                    | таблиця «Vocab-X polls»: відгуки, рядок на відгук                         |
| `GOOGLE_SPREADSHEET_ANALYTICS_ID`                                | таблиця «Vocab-X analytics»: листи «Події», «Сесії», «Відгуки», «Словник» |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`                         | запасний канал відгуків, коли таблиця недоступна                          |
| `DEVELOPER_CODE`                                                 | код, що відкриває режим розробника в налаштуваннях                        |

Обидві таблиці мають бути відкриті для `GOOGLE_CLIENT_EMAIL` з правами редактора. Ключі
використовуються лише на сервері (`/api/feedback`, `/api/track`) і ніколи не потрапляють у
клієнтський код. Згода, події й листи таблиці — у [ANALYTICS.md](ANALYTICS.md).

## Запуск

Потрібні Node.js ≥ 22 і pnpm (`npm i -g pnpm`).

```bash
pnpm install
pnpm dev           # http://localhost:3000 → /uk
pnpm typecheck     # TypeScript у всіх пакетах
pnpm lint          # ESLint, зокрема власні правила дизайн-системи та i18n
pnpm test          # Vitest (ядро, дані, теми, переклади, правила лінтера)
pnpm build         # production-збірка Next.js
pnpm e2e           # Playwright: усі тести, мобільний (390×844) і десктопний (1280×800) в'юпорти
pnpm e2e:changed   # лише тести того, що змінилося (див. нижче)
pnpm screenshots   # скріншоти /dev/ui і сторінок у 5 в'юпортах × 5 тем → apps/web/screenshots
```

Перед першим `pnpm e2e`: `pnpm --filter @vocabx/web exec playwright install chromium`.

**Вибіркові e2e-тести.** `pnpm e2e:changed` дивиться, які файли змінено (ще не закомічені, або
`--base main` — усе, чим гілка відрізняється від `main`), і запускає лише тести, що їх
покривають: карта «шлях → тести» — у `apps/web/scripts/e2e-changed.mjs`. Якщо змінився будь-який
інтерфейс (`.tsx`, `.css`, переклади, `public/`), додається `smoke.spec.ts`: кожна сторінка
відкривається без помилок у консолі й без горизонтальної прокрутки. Зміни налаштувань тестів
(`fixtures.ts`, конфіг Playwright, залежності) запускають усе. `--list` лише показує, що піде в
прогін. Перед пушем — повний `pnpm e2e`. Звук у тестовому браузері вимкнено: `--mute-audio` і
`NEXT_PUBLIC_SILENT_SPEECH=1` — системний голос Windows прапорця браузера не слухає, тож тестова
збірка вимовляє слова з нульовою гучністю.

Сторінка `/uk/dev/ui` показує всі компоненти в усіх темах. Вона доступна в `pnpm dev`;
у production-збірці — лише з `NEXT_PUBLIC_ENABLE_DEV_UI=1`.

**Режим розробника — за кодом.** Налаштування → «Режим розробника» питає код; його перевіряє
сервер (`/api/dev-unlock`, змінна `DEVELOPER_CODE` — лише на сервері, у браузер не потрапляє).
Відкритий режим (`AppSettings.devUnlocked`) дає перемикач «Панель розробника» (зсув часу,
способи навчання; Ctrl+Shift+D) і **полігон способів навчання** (`/review/lab`: той самий екран
повторення, спосіб і рівень — зі списків, слова по колу, нічого не зберігається й не йде в
статистику). Браузер, що відкрив режим, у статистиці позначається як внутрішній. Тести
Playwright запускають сервер із `DEVELOPER_CODE=test-code`. Сам код інструментів є в збірці;
закриває їх саме код, а не збірка (дані все одно лише локальні, на сервер вони не впливають).

## Структура

```
apps/web                 Next.js (App Router), Tailwind CSS v4, next-intl, Radix UI
  messages/<locale>/     переклади інтерфейсу (ICU), один JSON на простір імен
  src/app/[locale]/      маршрути; (app)/ — сторінки в оболонці, dev/ui — галерея компонентів
  src/components/ui/     Button, Card, Dialog, Tabs, Switch, ProgressBar, Toast, Avatar, Badge, Tooltip
  src/components/shell/  нижня панель (телефон), бічна панель (md+), колонка прогресу (lg+)
  src/themes/            реєстр тем і токени кольорів
  src/i18n/              реєстр локалей, маршрутизація, завантаження повідомлень
packages/core            чисті функції: FSRS-6, XP, стопка, оцінювання відповіді, журнал подій,
                         інтерфейси репозиторіїв, Clock/Rng, параметри моделі (src/config)
packages/content         реєстр мов, мовні адаптери, вбудовані колоди (src/decks/*.json)
packages/data            реалізації репозиторіїв: LocalStorageRepo (фаза A)
tools/eslint-plugin-vocabx  правила: design-tokens, no-jsx-literals
reference/               еталонні файли, з яких перенесено ядро
```

`core` не залежить від браузера чи Node: той самий код працюватиме на сервері у фазі B.

## Ключові рішення

- **Журнал подій — джерело істини.** Стан картки відтворюється з подій функцією `replayCard`;
  випадковий зсув інтервалу береться з `Rng`, засіяного `id` події, тож відтворення детерміноване.
- **Параметри моделі** (`w₀…w₂₀`, `ρ`, `τ⁰`, ліміти, пороги оцінювання, XP) — лише в
  `packages/core/src/config/params.ts`. Відхилення від класичного FSRS-6 (фаза вивчення в хвилинах,
  відновлення складності, бонус за серію, ранні успіхи у фазі вивчення) описано в шапці
  `packages/core/src/scheduler.ts`.
- **localStorage**: ключі `vocabx:v1:*`, `schemaVersion` з міграціями, компактний журнал,
  `StorageQuotaError` при переповненні, експорт/імпорт JSON з відкатом. UI звертається до даних
  лише через `useRepos()`; лінтер забороняє `localStorage` у компонентах.
- **Теми — набори семантичних токенів.** Стандартну палітру Tailwind вимкнено (`--color-*: initial`),
  тож `bg-white` чи `text-gray-900` не існують; правило `vocabx/design-tokens` додатково ловить
  сирі кольори, `dark:` і фізичні напрямки (`ml-`, `left-`, `text-right`). Тема застосовується
  inline-скриптом у `<head>` до гідратації — без «блимання».
- **Жодних рядків у JSX.** Правило `vocabx/no-jsx-literals` ловить текст і текстові атрибути
  (`aria-label`, `alt`, `placeholder`…). Тест перевіряє, що всі локалі мають однакові ключі й
  коректний ICU з тими самими аргументами.
- **«Назад» закриває вікна.** `useCloseOnBack` (`apps/web/src/lib/close-on-back.ts`) кладе в
  історію додатковий запис з тим самим URL, поки відкрите вікно; «Назад» знімає його й закриває
  вікно. `Dialog` і `Popover` з `components/ui` роблять це самі (крім `dismissible={false}`).
  Вікно, закрите кнопкою, прибирає свій запис кроком назад; якщо разом із закриттям застосунок
  переходить на іншу сторінку (`useRouter` з `@/i18n/navigation` про це повідомляє), нова
  сторінка займає місце запису — інакше крок назад скасував би перехід.
- **Доступність.** Контраст токенів кожної теми (WCAG AA) перевіряє unit-тест; сторінки — axe у
  Playwright. Цілі натискання ≥ 44 px, логічні властивості для RTL.

## Як додати тему

1. Файл `apps/web/src/themes/<id>.ts` з усіма токенами з `COLOR_TOKENS` і полем `unlock`
   (`free` | `level:N` | `achievement:id` | `purchase:sku`).
2. Запис у масиві `THEMES` у `apps/web/src/themes/registry.ts`.
3. Назва теми — ключ `<id>` у `messages/<locale>/themes.json` для кожної локалі.

`pnpm test` перевірить контраст усіх пар токенів.

## Як додати мову інтерфейсу

1. Папка `apps/web/messages/<code>/` з тими самими JSON-файлами, що й `uk/`.
2. Запис у `LOCALES` у `apps/web/src/i18n/locales.ts` (`dir: 'rtl'` для арабської, івриту тощо;
   `script` обирає резервний стек шрифтів).

`pnpm test` перевірить, що ключі й аргументи збігаються з українською локаллю.

## Колоди та велика колода

Повторюється одна велика колода: слова з усіх активних власних колод мови, від найбільш забутих.
Колоди лише визначають, що до неї входить: архівна колода — на паузі, а будь-яку колоду можна
повторити окремо (`/review?deck=<id>`). Денні ліміти необов'язкові й за замовчуванням вимкнені.
Де розгорнута бічна панель — задає `apps/web/src/components/shell/sidebar-config.ts`.

## Як додати вбудовану колоду

1. JSON-файл у `packages/content/src/decks/` (формат — `DeckFile` у `decks/index.ts`): слова з частиною
   мови, перекладами за кодом мови та прикладами.
2. Запис у `DECK_FILES`. `pnpm test` перевірить унікальність лем, наявність перекладів і те, що
   приклад містить слово.
3. Тематична колода (не рівнева A1–C2) має поле `topic`; рівень `cefr` — типовий для теми (для
   сортування в бібліотеці). Тест рівня тематичні колоди не використовує.

Тест рівня бере слова з двох фіксованих списків на кожен рівень (перша спроба й повторна, без
спільних слів): `packages/content/src/placement.ts`. У списку — слова, що задаються спершу (A1 3,
A2 4, B1 5…), і ще 3 на випадок помилки. Неправильні варіанти — з решти слів колоди рівня.

Переклади нових слів, які додає користувач, підказують Google Translate і Wiktionary (переклади),
Wiktionary та Free Dictionary (частина мови, приклади) — з тайм-аутом, кешем і ручним введенням як
запасним варіантом (`apps/web/src/lib/lexicon`). Google Translate (Cloud Translation API v2)
викликає сервер — `/api/translate` — від імені того самого сервісного акаунта Google
(`GOOGLE_CLIENT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `GOOGLE_PROJECT_ID`); у проєкті Google Cloud має
бути увімкнено Cloud Translation API. Без цих змінних переклад просто не підказується.

## Режим «Речення» і приклади

Ядро — `packages/core/src/sentence.ts`: `clozeOf` знаходить слово в прикладі (саме слово, лему,
варіант або форму: для англійської — правильні закінчення, щоб «convenience» не вважалось
формою «convenient»; для інших мов — основа без двох останніх літер і коротке закінчення);
`clozeForReview` бере приклад за числом відповідей картки (`reps`), тож вони чергуються, а
помилка (рівень не знижується: `mistakeKeepsLevel` у параметрах планувальника) приводить інше
речення. Кожна правильна відповідь у реченнях — наступний рівень (3 → 1), без умов
планувальника про паузу й стабільність: рівні речень рахує `applyEvent`
(`packages/core/src/events.ts`). Формати `SENT_PICK`, `SENT_SAY`, `SENT_TYPE` дописані в
кінець `ALL_FORMATS`.

## Змішаний режим

Режим за замовчуванням (`AppSettings.mixedMode`; `quizMode` і `sentenceMode` мають перевагу,
усі три вимкнені — картки). Коло кроків — `MIXED_STEPS` у `packages/core/src/types.ts`
(q1 s1 q2 q3 s2 s3). Крок слова — `CardState.mix`, помилки поспіль на ньому — `misses`; без
кроку (нове слово чи відповідь в іншому режимі) його дає рівень (`mixedStepOf`). Відповідь у
змішаному режимі позначена в журналі `kind: 'mixed'` (у стиснутому записі — прапорець `2` у
кінці кортежу), тож повторне відтворення журналу дає ті самі кроки; відповідь в іншому режимі
крок скидає. Правильна — крок уперед (після шостого — перший), дві помилки поспіль — крок
назад. Слово без прикладу на кроці речення питається тестом того ж рівня.

Слово зберігає до `MAX_EXAMPLES` (5) прикладів. Вбудовані колоди мають по одному: писати ще по
чотири для кожного з ~450 слів означало б ~1 800 неперевірених речень, які щоразу завантажувалися
б у браузер кожного користувача, хоча більшість слів ніхто з них не дійде до речень. Натомість
`useExampleTopUp` (`apps/web/src/lib/lexicon/example-top-up.ts`) у режимі «Речення» у фоні шукає
приклади для слів поточного повторення, яким їх бракує (до 10 слів за сесію, по одному запиту, з
кешем словників), і зберігає знайдене разом зі словом. Слово без жодного придатного прикладу
питається як тест із 4 варіантів.

Тури сторінок — `components/tour/page-tour.tsx` (геометрія спільна з туром головної:
`components/tour/geometry.ts`): кроки з позначками `data-tour`, тексти — `messages/*/tours.json`,
що бачили — `lib/home-tour.ts`. Крок із `hidden: true` (і в турі головної) пропускається, але
лишається в коді разом із текстами; тур без жодного видимого кроку не показується. Підказка
до «Знайти» у вікні «Додати слово» — картка всередині вікна (`FindTip`), бо тур поверх
модального вікна сперечався б із його пасткою фокуса. Полігон тримає три останні відповіді для
«Скасувати»; змішаний режим на полігоні йде кроками по черзі, без вибору рівня.

`clozeOf` вирізає кожне входження слова (`parts` і `answers`). Полігон (`/review/lab`) — це
`ReviewSession` з `lab`: спосіб і рівень задаються списками, `grade` лише переносить картку в
кінець стопки, нічого не пише в сховище й не надсилає подій.

Розпізнавання мови — Web Speech API (`apps/web/src/lib/speech-recognition.ts`), без запису на
стороні застосунку.

## Як додати формат вправи

1. Рендерер у `apps/web/src/components/review/formats/`: компонент, що отримує `FormatProps`
   (`card`, `side`, `typing`, `onTypedSubmit`…) і малює лише вміст картки, та об'єкт
   `FormatRenderer` (`format`, `supportsTyping`, `frontText`).
2. Запис у масиві в `formats/registry.ts`. Оболонка `ReviewSession` (прогрес, оцінки, свайпи,
   клавіші, скасування, підсумок) не змінюється.

## Демонстрація інтервального повторення

У режимі розробника (див. вище) «Панель розробника» (або Ctrl+Shift+D) відкриває зсув часу:
«+1 день», «+7 днів». Рухається лише годинник застосунку; збережені дані не змінюються.

## Як додати мову, що вивчається

1. `packages/content/src/adapters/<code>.ts` — адаптер (`createBasicAdapter` з правилами нормалізації).
2. Один запис у `LANGUAGES` у `packages/content/src/languages.ts`.

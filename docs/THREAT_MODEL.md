# VocabX — threat model (step 2.6)

Written in session 15 (2026-11-13) from the code, not from other documents: every protection named
here was read in the file given and has the test given. Paths are under `apps/web/src/` unless
they start with `packages/`. "Residual" is what the protection leaves open, accepted for launch.
Update this table whenever a protection changes; findings of the pre-launch audit are in
`docs/AUDIT.md` (A1–A12).

## 2. Weak spots found and fixed (session 15, approved by the owner 2026-11-13)

| Id  | Weak spot                                                                                                                     | Fix                                                                                                                                                                                           |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| W1  | A session (JWT, 30 days) could not be ended: a new password or a reset left other devices signed in; no "sign out everywhere" | `users.sessions_since` (migration `0007`), `authAt` in the cookie, `liveAccount` on every route that reads the account row; profile button; 401 from sync signs the device out with a message |
| W2  | A confirmation link (lives a day, travels in a URL, so in request logs) also set a password through `/api/account/reset`      | Reset tokens hashed with a kind of their own (`resetHash`): only the reset letter's link sets a password                                                                                      |
| W3  | `/api/account/reset` (setting) ran scrypt before looking at the token, with no limit; `/api/account/verify` had no limit      | Token looked up first, scrypt only for a real one; 20 tries / 15 min per sender (database); verify 30 / 10 min per sender (memory)                                                            |
| W4  | No tests for the developer code, the cron secret, the dictionary proxy's addresses, the raw-HTML sinks                        | `app/api/guards.test.ts`                                                                                                                                                                      |

## 3. If a key leaks

Change it in the Vercel project settings and redeploy; the table says what else to do and what
the change breaks. Switch the matching feature off first if it costs money (`KILL_*`, see
`lib/kill-switch.ts`).

| Key                                          | What it gives                                                   | Rotate                                                           | What the change breaks                                                                                                                      |
| -------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `NEXTAUTH_SECRET`                            | Forging a session for any account: all its synced data          | New random value                                                 | Everyone is signed out; rate-limit counts start anew (their keys are hashed with it); a registration's link confirms but no longer signs in |
| `DATABASE_URL` (+ `_DIRECT`)                 | The whole database                                              | Reset the role's password in Neon                                | Nothing for learners                                                                                                                        |
| `GOOGLE_PRIVATE_KEY` / `GOOGLE_CLIENT_EMAIL` | The spreadsheets (analytics, feedback, reminders) and Translate | `KILL_TRANSLATE`; delete the key in Google Cloud, make a new one | Nothing for learners                                                                                                                        |
| `GOOGLE_CLIENT_SECRET`                       | Posing as the app's Google sign-in                              | New secret in Google Cloud                                       | Nothing for learners                                                                                                                        |
| `EMAIL_SERVER_PASSWORD`                      | Sending mail as the app's account                               | `KILL_REGISTRATION`; revoke the app password, make a new one     | Letters stop until the new one is set                                                                                                       |
| `TELEGRAM_BOT_TOKEN`                         | Posting as the feedback bot                                     | `/revoke` in BotFather                                           | Nothing for learners                                                                                                                        |
| `VAPID_PRIVATE_KEY`                          | Sending pushes to subscribed browsers                           | New key pair (public key too)                                    | Every reminder subscription ends; learners turn reminders on again                                                                          |
| `CRON_SECRET`                                | Running the cleanup and the reminders early                     | New random value (Vercel Cron picks it up)                       | Nothing                                                                                                                                     |
| `DEVELOPER_CODE`                             | The developer panel in a browser (no server rights)             | New value                                                        | Developers unlock again                                                                                                                     |

## 4. Accepted for launch (no code)

- Limits counted per server instance (`track`, `push`, `push/test`, `dictionary`, `verify`,
  translate's burst): they slow one instance, not a spread-out flood. The owner's rule (session 3):
  the database must not be woken for them.
- Unauthenticated routes that open the database (sign-in, registration, reset, translate) can keep
  Neon awake and use up the free compute hours; Vercel's attack challenge mode is the manual answer.
- Whoever knows a push subscription's address can switch its reminder off or send it test pushes
  (AUDIT §6.3); the address is unguessable.
- The confirmation token travels in a query string (`/api/account/verify?token=`), so it can be in
  Vercel's request logs (owner-only) for a day; since W2 it can only confirm the address.

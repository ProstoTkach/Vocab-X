# VocabX — pre-launch audit (step 0.1)

Date: 2026-11-12. Scope: every item of phases 1–5 of `docs/PRELAUNCH_PLAN.md`, checked against
the working tree (uncommitted changes included). Paths are relative to `apps/web/` unless they
start with `packages/`, `docs/` or `.github/`.

Status: **done** / **partial** / **missing**. Nothing in the code was changed by this step.

How it was checked: all 14 API routes and the auth, sync, league, push, e-mail and analytics
libraries were read; `pnpm audit --prod` was run; git history (35 commits) was searched for
`.env*` files and private keys. **Not** done here: `pnpm build` + `.next` secret scan (step 2.4),
any run against a real database, any browser run.

## 6. Not on the list

1. **A1** (pre-hijack) and **A8** (no reset) — not named in the plan; belong in 5.3, which should move before 2.x.
2. **Reminders run once a day.** The only cron is `0 17 * * *` (`vercel.json`), while each phone plans its own time (`push/cron/route.ts:19-23`): a reminder due at 18:00 UTC goes out 23 hours late. Needs an hourly schedule (Vercel plan permitting) or an outside scheduler.
3. **`/api/push` and `/api/push/test` take no sign-in or consent proof.** Whoever knows a subscription address can switch a reminder off or send test pushes. The address is hard to guess, so risk is low; the test route should be open to developers only.
4. **Deleted account, live cookie:** `/api/league` answers 500 instead of 401 (see 1.5).
5. **`users.deleted_at`** is filtered on everywhere and set nowhere. Either drop it or make deletion soft with the 30-day purge of step 1.6 — decide in 1.6.
6. **League names** are free text up to 40 characters shown to strangers (`league/route.ts:23`): no XSS (React escapes), but no filter for abuse and no way to report.
7. **Feedback copy failures are silent** and feedback has two stores (polls sheet, analytics sheet, Telegram fallback): deletion requests must cover all three (for DATA_MAP).
8. **`.env.example` variable list** (from code): `DATABASE_URL`, `DATABASE_URL_DIRECT`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_CLIENT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `GOOGLE_PROJECT_ID`, `GOOGLE_SPREADSHEET_ANALYTICS_ID` (+ the polls spreadsheet id read in `lib/google-sheets.ts`), `EMAIL_SERVER_USER`, `EMAIL_SERVER_PASSWORD`, `EMAIL_SERVER_HOST`, `EMAIL_SERVER_PORT`, `EMAIL_FROM`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `CRON_SECRET`, `DEVELOPER_CODE`, `NEXT_PUBLIC_ENABLE_DEV_UI`, `NEXT_PUBLIC_ANALYTICS_ON_LOCALHOST`, `NEXT_PUBLIC_SILENT_SPEECH`, `TEST_USER_PASSWORD`.
9. **VAPID subject falls back to a hard-coded address** `https://vocabx-sigma.vercel.app` (`lib/push.ts:59`); should come from `NEXTAUTH_URL`.

## 7. Change plan (for approval)

Status: approved by the owner and applied to `docs/PRELAUNCH_PLAN.md` on 2026-11-12 (the order
below is superseded by the plan's "Sessions" table; decisions 2 and 3 at the end are made, see
step 2.1 of the plan). Original proposal:

1. **New step 1.0 (before 1.1), model O: fix A1.** Smallest safe fix: a second registration of an unconfirmed address must not replace the password silently — keep the pending password with its token, and let a link confirm only the password that was set together with it; the newest letter wins, older links die. Tests for both orders of the two registrations. Full fix needs the reset flow (below).
2. **Step 2.1 first among phase 2, and split:** (a) shared limiter (Neon table, fixed window) + `translate`, `register`, sign-in, `dev-unlock` — these four are A2–A4, A10; (b) `track`, `feedback`, `push`, `sync`, `league`, `Retry-After`, client messages. `track` must be keyed by sender address (hashed, short-lived), not `anon_id`.
3. **Step 5.3 moves up, right after 2.2**, and gains: password reset flow (A8), `Origin` check on custom routes, sign-in enumeration, 401 for deleted accounts in `league`.
4. **Step 2.2 gains:** body caps for `sync` and `feedback`, upper bound for event time, per-user row quota.
5. **Step 2.5 gains:** `nodemailer` → ≥ 10.1.4 (check next-auth's peer range; e-mail sign-up must be re-tested by hand).
6. **Step 1.5 gains:** unsubscribe + remove the Sheets row on account deletion (A11); becomes simple after 3.1 moves subscriptions to Neon with an optional `user_id`.
7. **Step 1.2 gains:** server accepts only known `params` keys per event, or the test checks every `track()` call site.
8. **Step 1.6 gains:** decision on `users.deleted_at` and the reminder schedule (item 2 of section 6).

Proposed order: 0.1 → **1.0** → 1.1 → 1.2 → **2.1a** → 1.3 → 1.4 → 1.5 → 1.6 → 2.1b → 2.2 → **5.3** → 2.3 → 2.4 → 2.5 → 2.6 → 5.1, 5.2, 5.4–5.6 → phase 3 → phase 4 → 5.7–5.11.

Owner's decisions needed: (1) approve the plan changes above; (2) where the shared rate-limit store lives (Neon table is proposed: no new service); (3) whether sign-in may be required for `/api/translate` (cheapest protection) or it stays open with a limit per sender.
